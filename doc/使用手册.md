## 1. CLI快速开始

### 1.1 基础命令

定制码匠提供三个主要交互模式：

```bash
# 交互式TUI模式（推荐日常使用）
code-agent tui

# 带初始提示的TUI模式（启动后自动发送提示）
code-agent tui "修复src/auth.rs中的空指针异常"

# 非交互式执行模式（适合CI/CD和脚本）
code-agent exec "修复src/auth.rs中的空指针异常"

# App Server模式（为IDE插件提供后端服务）
code-agent app-server
```

### 1.2 三条命令一分钟上手

```bash
# 1. 检查环境
code-agent doctor
# 输出: ✅ 所有检查通过

# 2. 进入项目目录并启动TUI
cd my-project
code-agent tui

# 3. 开始对话：直接输入你的编码需求
💬 > 帮我给User模型添加created_at和updated_at字段

# 或者启动时直接指定任务
code-agent tui "帮我给User模型添加created_at和updated_at字段"
```

### 1.3 Exec模式（非交互式）

适合CI/CD流水线、Shell脚本集成、批量处理：

```bash
# 基础用法
code-agent exec "任务描述"

# 指定工作目录
code-agent exec --cwd /path/to/project "实现UserService接口"

# 指定输出格式
code-agent exec --output json "分析当前项目的依赖关系"

# 设置超时时间（秒）
code-agent exec --timeout 120 "为所有Controller生成单元测试"

# 从stdin管道读取任务
echo "检查代码中的SQL注入漏洞" | code-agent exec

# 管道输出到文件
code-agent exec "生成项目架构文档" > architecture-report.md
```

**退出码**：

| 退出码 | 含义 |
|--------|------|
| 0 | 任务成功完成 |
| 1 | Agent执行出错 |
| 2 | 工具调用失败 |
| 3 | 超时 |

### 1.4 配置管理

```bash
# 初始化配置
code-agent config init            # 生成用户级默认配置
code-agent config init --project  # 生成项目级配置

# 查看配置
code-agent config show            # 显示所有生效配置
code-agent config show --source   # 显示每项配置的来源

# 修改配置
code-agent config set agent.max_turns 50
code-agent config set models.temperature 0.8

# 查看配置路径
code-agent config path
```

## 2. TUI界面操作指南

### 2.1 界面布局

启动`code-agent tui`后，终端分为三个区域。TUI 通过双向通道与 Agent 引擎实时通信：用户输入通过 `mpsc` 通道发送给 Agent，Agent 的流式响应（推理过程、工具调用、最终回答）通过事件通道实时推送回 TUI 渲染。

> **v0.2 更新**：TUI 现已完整接入 Agent 引擎。`cmd_tui()` 创建真实的 `ModelClient`、`ToolRegistry` 和 `Session`，用户消息经 ReAct 循环处理后流式返回。此前 `_tx` 被丢弃导致 Agent 无法接收消息的 Bug 已修复。

```

│  🧠 定制码匠 · CraftCoder              Session: abc123 │  ← 状态栏
├──────────────────────────────────────────────────────┤
│                                                      │
│  🤖 你好！我是定制码匠，基于推理模型（通过 LLM_CHAT_MODEL 配置）的AI编程助手。    │
│     当前项目：user-service（Java/Spring Boot）          │
│     已索引文件：247个                                   │
│                                                      │  ← 聊天面板
│  💬 > 帮我分析UserController的潜在性能问题               │
│                                                      │
│  [Thinking] 正在分析UserController.java...             │
│  - 扫描到12个接口方法                                   │

│                                                      │
├──────────────────────────────────────────────────────┤
```

## 3. 代码编辑工作流

### 3.1 标准工作流：生成 → 审查 → 接受/拒绝

定制码匠的代码编辑采用三步确认流程，确保开发者始终拥有最终控制权：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ 1. 生成      │ → │ 2. Diff预览  │ → │ 3. 确认      │
│ AI分析需求   │    │ 展示变更内容  │    │ 接受/拒绝/修改 │
│ 生成代码     │    │ 逐文件对比    │    │ 一键回滚     │
└─────────────┘    └─────────────┘    └─────────────┘
```

#### 步骤1：描述需求

```
💬 > 在UserService中添加基于Redis的登录失败次数限制，5分钟内失败5次锁定账户30分钟
```

#### 步骤2：审查Diff

Agent生成代码后，展示变更的Diff预览：

```
📝 变更预览（2个文件）:

  src/service/UserService.java  (+35 lines, -2 lines)
  src/config/RedisConfig.java   (+12 lines, new file)

  ─── Diff: src/service/UserService.java ───
  + @Autowired
  + private RedisTemplate<String, Integer> redisTemplate;
  +
  + private static final int MAX_ATTEMPTS = 5;
  + private static final int WINDOW_MINUTES = 5;
  + private static final int LOCK_MINUTES = 30;
  +
  + public LoginResult login(String username, String password) {
  +     String key = "login:attempts:" + username;
  +     Integer attempts = redisTemplate.opsForValue().get(key);
  +     ...
```

#### 步骤3：确认操作

```
操作选项:
  [A] 接受全部变更  [R] 拒绝全部变更  [F] 逐文件审查  [M] 修改后重试
```

### 3.2 支持的文件操作

Agent通过以下工具操作文件系统：

| 工具 | 功能 | 权限级别 |
|------|------|:---:|
| `read_file` | 读取文件内容（支持指定行范围） | 🟢 低风险 |
| `write_file` | 创建或覆盖文件 | 🟡 中风险 |
| `edit_file` | 精确编辑（search-replace模式） | 🟡 中风险 |
| `list_dir` | 列出目录内容 | 🟢 低风险 |
| `grep` | 正则表达式搜索文件内容 | 🟢 低风险 |
| `glob` | 文件名模式匹配搜索 | 🟢 低风险 |

### 3.3 Exec模式下的代码生成

```bash
# 生成代码并直接写入文件（需确认）
code-agent exec "在src/utils/下创建DateHelper.java工具类" --auto-approve

# 仅预览变更，不写入文件（Dry Run）
code-agent exec "重构UserService" --dry-run

# 指定输出文件
code-agent exec "生成README.md" --output README.md
```

### 3.4 交互反模式（应避免的操作方式）

| ❌ 不推荐 | ✅ 推荐 |
|-----------|--------|
| "帮我重构整个项目"（目标过大） | "把UserService中的缓存逻辑抽取到独立的CacheService" |
| "修复所有bug"（范围模糊） | "修复src/auth/login.rs中的空指针异常" |
| 一次性提交多个不相关的更改 | 每个独立变更为一个单独请求 |
| 不审查Diff直接全部接受 | 逐文件审查，确认每处变更 |

## 4. AI Code Review使用

### 4.1 PR审查

定制码匠可以自动审查Git Pull Request，生成结构化的审查报告：

```bash
# 审查指定PR
code-agent exec --format markdown "审查PR #42，重点关注安全性和性能" > pr42-review.md

# 审查当前分支相对于main的变更
code-agent exec "审查当前分支的代码变更"

# 审查指定commit范围
code-agent exec "审查HEAD~5..HEAD的代码变更"
```

### 4.2 审查报告格式

AI Code Review报告包含四类审查结果：

```markdown
# Code Review Report — PR #42

## 🔴 BLOCKER（必须修复）— 1项
📍 src/auth/login.ts:42-58
🔍 类型: 安全漏洞
📋 问题: 密码错误未区分"用户不存在"和"密码错误"，存在用户枚举漏洞
💡 修复建议: 使用统一的模糊错误消息"用户名或密码错误"
🔧 [一键应用修复]

## 🟠 CRITICAL（建议修复）— 3项
📍 src/service/order.rs:156
🔍 类型: 性能问题
📋 问题: 循环内执行数据库查询，建议使用批量查询
💡 修复建议: 使用IN查询或BatchFetch模式

## 🟡 MINOR（值得关注）— 5项
📍 src/model/user.rs:23
🔍 类型: 代码风格
📋 问题: 变量命名不符合Java命名规范

## 🔵 SUGGESTION（优化建议）— 2项
📍 src/utils/helper.rs:89
🔍 类型: 最佳实践
📋 问题: 建议使用Optional替代null返回值

## 安全扫描结果（安全审查模型）
✅ 无安全漏洞检测到
```

### 4.3 Code Review触发方式

| 触发方式 | 配置 | 说明 |
|----------|------|------|
| **手动触发** | `code-agent exec "审查当前变更"` | 按需审查 |
| **Git Hook** | 配置Pre-commit Hook | 提交前自动审查 |
| **CI集成** | GitHub Actions / GitLab CI | PR/MR自动触发 |
| **文件保存** | IDE插件配置 | 保存文件时自动审查（仅当前文件） |

### 4.4 质量门禁配置

在CI流水线中配置质量门禁：

```yaml
# .github/workflows/ci.yml（片段）
- name: AI Code Review
  run: |
    code-agent exec "审查当前PR变更" --format json --strict > review.json
    
    # 检查BLOCKER数量
    BLOCKERS=$(jq '.blocker_count' review.json)
    if [ "$BLOCKERS" -gt 0 ]; then
      echo "❌ PR包含${BLOCKERS}个BLOCKER级别问题，已阻断合并"
      exit 1
    fi
```

## 5. 驾驭工程配置

### 5.1 编码标准管理

在项目根目录的`.code-agent/`目录下配置团队编码标准：

```bash
# 目录结构
.code-agent/
├── config.toml          # 项目配置
├── standards/
│   ├── java-style.md    # Java编码规范
│   ├── python-style.md  # Python编码规范
│   ├── naming.md        # 命名约定
│   └── architecture.md  # 架构约束规则
└── rules/
    ├── security.md      # 安全编码规则
    └── review.md        # Code Review规则
```

### 5.2 配置架构约束

在`architecture.md`中定义架构规则：

```markdown
# 架构约束规则

## 分层约束
- Controller层不可直接访问DAO层，必须通过Service层
- Service层不可包含HTTP相关代码
- 工具类不可依赖业务模块

## 依赖方向
- domain ← application ← infrastructure ← presentation
- 不允许反向依赖
- 不允许循环依赖（由Rust循环检测模块自动检查）
```

Agent在进行代码生成和审查时会自动遵循这些规则。

## 6. VS Code扩展使用

### 6.1 安装

1. 从VS Code Marketplace安装或从`.vsix`文件手动安装
2. 确保`code-agent` CLI已安装并可用
3. 打开任意项目文件夹

### 6.2 核心功能

| 功能 | 触发方式 | 说明 |
|------|----------|------|
| **Agent对话** | 侧边栏（Cmd+Shift+P → CraftCoder: Open Chat） | 在侧边栏与Agent对话 |
| **内联编辑** | 选中代码 → Cmd+K → 输入自然语言指令 | 选中代码后直接描述修改需求 |
| **智能补全** | 输入时自动触发 | 内联幽灵文本，Tab键接受 |
| **Bug修复** | 右键菜单 → "CraftCoder: Explain & Fix" | 选中错误代码，自动分析并修复 |
| **文档生成** | 右键菜单 → "CraftCoder: Generate Docs" | 为当前函数/类生成文档注释 |
| **测试生成** | 右键菜单 → "CraftCoder: Generate Tests" | 为当前函数生成单元测试 |
| **代码审查** | 保存文件时自动触发 | 自动审查当前文件的代码质量 |

### 6.3 侧边栏对话

VS Code侧边栏中的Agent对话面板支持：

- 多轮对话（保留上下文）
- 流式输出（实时显示Agent推理过程）
- Diff预览（变更在编辑器中高亮显示）
- 一键接受/拒绝变更
- 工具调用可视化（正在读取文件、执行Shell等）

在VS Code设置（`settings.json`）中可配置：

```json
  "craftcoder.review.onSave": true,
  "craftcoder.completion.enabled": true,
  "craftcoder.completion.delay": 300,

```

## 7. Web API使用

### 7.1 启动Web API服务

```bash
# 启动App Server（含Web API）
code-agent app-server --host 0.0.0.0 --port 8080

# 或通过Docker
docker compose up -d
```

### 7.2 API端点

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/threads` | 创建新的Agent会话线程 |
| `POST` | `/threads/:id/turns` | 提交用户消息，返回SSE事件流 |
| `GET` | `/threads/:id/events` | 获取线程事件历史 |
| `DELETE` | `/threads/:id` | 删除/归档线程 |
| `GET` | `/threads` | 列出所有线程 |
| `GET` | `/health` | 健康检查 |

### 7.3 使用示例

#### 创建线程

```bash
curl -X POST http://localhost:8080/threads \
  -H "Content-Type: application/json" \
  -d '{
    "title": "修复登录Bug",
    "cwd": "/path/to/project"
  }'
# 响应: {"thread_id": "ses_abc123", "status": "active"}
```

#### 提交任务并流式获取结果（SSE）

```bash
curl -X POST http://localhost:8080/threads/ses_abc123/turns \
  -H "Content-Type: application/json" \
  -d '{"message": "修复src/auth/login.rs中的空指针异常"}'

# SSE事件流响应:
# event: TurnStarted
# data: {"turn_id": 1}
#
# event: AgentMessageDelta
# data: {"content": "我来分析src/auth/login.rs代码..."}
#
# event: ToolCallBegin
# data: {"tool": "read_file", "args": {"file_path": "src/auth/login.rs"}}
#
# event: ToolCallEnd
# data: {"tool": "read_file", "success": true, "output": "..."}
#
# event: TurnCompleted
# data: {"turn_id": 1, "answer": "已修复第42行的空指针异常", "tokens_used": 3420}
```

#### JavaScript/TypeScript客户端示例

```typescript
// 使用EventSource监听SSE事件流
const sse = new EventSource('http://localhost:8080/threads/ses_abc123/events');

sse.addEventListener('AgentMessageDelta', (e) => {
    const { content } = JSON.parse(e.data);
    console.log('Agent:', content);
});

sse.addEventListener('ToolCallBegin', (e) => {
    const { tool, args } = JSON.parse(e.data);
    console.log(`🔧 调用工具: ${tool}(${JSON.stringify(args)})`);
});

sse.addEventListener('TurnCompleted', (e) => {
    const { answer } = JSON.parse(e.data);
    console.log('✅ 完成:', answer);
    sse.close();
});
```

## 8. 故障排除

### 8.1 常见问题

#### Q: TUI界面显示乱码

确保终端支持UTF-8编码和真彩色（24-bit color）。

```bash
# 检查终端类型
echo $TERM
# 推荐: xterm-256color 或 screen-256color

# Windows Terminal设置
# 设置 → 配置文件 → 外观 → 颜色方案: Campbell
```

#### Q: Agent卡在某个工具调用不返回

```bash
# 按Ctrl+C中断当前操作
# Agent会保存已完成步骤并返回部分结果

# 或调整超时配置
code-agent config set agent.turn_timeout_seconds 60
```

#### Q: 代码生成质量不理想

```bash
# 1. 确保项目已正确索引
# Agent会自动索引项目，也可以手动触发：
# （首次启动时自动执行）

# 2. 调整推理参数
code-agent config set models.temperature 0.3   # 降低随机性（更精确）
code-agent config set models.enable_thinking true  # 启用思维链
```
